## 📋 ПРАВИЛА ФОРМАТИРОВАНИЯ

### 1. Заголовок

- **Без эмодзи** (эмодзи добавится автоматически)
- **Без специальных символов** Markdown
- **На русском языке**
- Максимум 80 символов

**Примеры:**
```
✅ "Node.js выпустил экстренные security-патчи"
✅ "PHP 8.4: новые возможности для разработчиков"
❌ "🔥 Node.js Emergency Release!!!"  # Эмодзи и английский
```

### 2. Описание

- **2-3 предложения** на русском
- **Без ссылок** и хэштегов
- Краткое содержание статьи

**Примеры:**
```
✅ "Node.js выпустил экстренные обновления для всех активных версий. Исправлены 9 уязвимостей, включая 2 критические."
❌ "Node.js project released emergency updates... #security"  # Английский и хэштеги
```

### 3. Статья (content)

**НЕ включай заголовок в начале!** Telegra.ph добавит его автоматически.

**Используй Markdown:**
- `## Раздел` — заголовки разделов
- `**жирный текст на русском**` — выделение важного **НА РУССКОМ!**
- `· Пункт` — маркированные списки
- `[ссылка](url)` — ссылки
- ```` ```код``` ```` — блоки кода

**ВАЖНО: Внутри **жирного** тоже пиши на русском!**

**НЕПРАВИЛЬНО:**
```markdown
· **Critical** — 1 уязвимость  # Английское слово!
· **High** — 11 уязвимостей    # Английское слово!
```

**ПРАВИЛЬНО:**
```markdown
· **Критический** — 1 уязвимость
· **Высокий** — 11 уязвимостей
```

**Пример структуры:**
```markdown
Введение на русском языке (2-3 предложения, без заголовка).

## Детали уязвимостей

Текст с **выделением важного на русском**.

· CVE-2026-21637 (высокий уровень) — описание на русском
· CVE-2026-21710 (высокий уровень) — описание на русском

## Что делать

Рекомендации на русском.

---

Источники:
· Источник 1
· Источник 2
```

### 4. Хэштеги

- **Без символа #** (добавится автоматически)
- **На русском** или английском (технические термины)
- 3-5 штук

**Примеры:**
```
✅ ["javascript", "security", "nodejs"]
✅ ["ai", "нейросети", "технологии"]
❌ ["#javascript", "#ai"]  # Без решётки!
```

## 🔍 РАБОЧИЙ ПРОЦЕСС

### Шаг 1: Проверка истории публикаций (КРИТИЧЕСКИ ВАЖНО!)

**ПЕРЕД генерацией темы** открой `06_history/01_published_posts.md` и найди все публикации за последние **30 дней**.

Выпиши темы, которые уже публиковались:
- Какие продукты/технологии упоминались
- Какие версии выходили
- Какие события освещались

**ЗАПРЕЩЕНО** генерировать тему, если:
- Такой же продукт уже был в заголовке за последние 30 дней
- Такая же версия продукта уже упоминалась
- Событие слишком похоже на недавнюю публикацию

**Пример проверки:**
```
Если в истории есть:
  2026-03-29: "VS Code перешёл на еженедельные релизы: версия 1.111"

То НЕЛЬЗЯ генерировать:
  ❌ "VS Code 1.111: еженедельные релизы и AI-автопилот"
  ❌ "Visual Studio Code версия 1.111"
  ❌ "VS Code: новый цикл релизов"

Можно генерировать только если:
  ✅ Про VS Code прошло 30+ дней
  ✅ Или это критическая security-новость (экстренный случай)
```

### Шаг 2: Исследование источников

Изучи файлы:
- `02_sources/02_github_repos.md` — GitHub репозитории
- `02_sources/01_rss_feeds.md` — RSS ленты
- `02_sources/03_telegram_channels.md` — Telegram каналы
- `02_sources/04_technical_blogs.md` — Технические блоги

Найди **свежую новость (48 часов)**, которая НЕ пересекается с темами из Шага 1.

### Шаг 3: Проверка уникальности темы

Открой `06_history/02_topics_covered.md` и проверь, не публиковалась ли такая тема в этой категории.

Если тема похожа на недавнюю — **ВЫБЕРИ ДРУГУЮ новость**.

### Шаг 4: Генерация данных

Создай JSON с данными:
1. Заголовок на русском
2. Описание на русском
3. Статья на русском с Markdown
4. Хэштеги без #
5. Источники

### Шаг 5: Публикация

Запусти скрипт:
```bash
python3 /root/git/AI-journalist/publisher_final.py --input /tmp/ai_news.json
```

### 4. ПРОВЕРЯЙ ИСТОРИЮ — НЕ ГЕНЕРИРУЙ ДУБЛИКАТЫ

**КРИТИЧЕСКИ ВАЖНО:** Перед генерацией темы открой `06_history/01_published_posts.md` и проверь публикации за последние **30 дней**.

**Если тема похожа на недавнюю — НЕ ГЕНЕРИРУЙ ЕЁ!** Выбери другую новость.

**Пример:**
```
❌ НЕЛЬЗЯ: Генерировать "VS Code 1.111" если 2026-03-29 уже было "VS Code перешёл на еженедельные релизы: версия 1.111"
✅ МОЖНО: Подождать 30 дней или выбрать другую тему (Python, Rust, AI и т.д.)
```

**Помни:** Таймер запускается каждый час. Если AI сгенерирует дубликат — публикация будет заблокирована, и канал останется без новостей.

## 🐛 ИЗВЕСТНЫЕ ОШИБКИ

### Ошибка: "Bad Request: can't parse entities"

**Причина:** Проблемы с Markdown

**Решение:**
- Проверь парность `**`, `_`
- Проверь ссылки `[текст](url)`
- Не экранируй символы вручную (скрипт сделает это сам)

### Ошибка: статья на английском

**Причина:** AI не прочитал системный промпт

**Решение:**
- ВСЕГДА пиши на русском
- Заголовок, описание, статья — всё на русском
