### 2026-03-25: Telegram анонс — лишняя строка "Читать:"

**Ошибка:**
В анонсе была отдельная строка "Читать: URL".

**Решение:**
Ссылка в заголовке через Markdown:
```
🤖 [Заголовок статьи](URL)

Описание обычным текстом.
```

**Правило:** Ссылку добавлять к заголовку, не использовать отдельную строку "Читать:".

### 2026-03-25: Telegra.ph — дублирование заголовка

### 2026-03-25: Telegra.ph — дублирование заголовка

**Ошибка:**
Заголовок статьи дублировался в контенте:
1. Telegra.ph добавляет заголовок из параметра `title`
2. Первый параграф контента = заголовок статьи

**Результат:**
Заголовок отображался дважды подряд.

**Решение:**
1. В параметр `title` передаём заголовок статьи
2. В контенте пропускаем первый заголовок (`skip_first_h3=True`)
3. В контенте пропускаем первый параграф (`skip_first_paragraph=True`)
4. Контент начинается сразу с описания, без заголовка

**Правильная структура:**
```python
article_content = """Описание статьи (без заголовка)

Разобрали N ситуаций...

## 1. Раздел первый
...
"""

content_nodes = create_telegraph_content(
    article_content,
    include_title=False  # Пропускаем заголовок и первый параграф
)

data = {
    "title": "Заголовок статьи",  # Telegra.ph добавит автоматически
    "content": json.dumps(content_nodes)
}
```

**Правило:** Не включай заголовок в контент статьи — Telegra.ph добавляет его автоматически из параметра `title`.

### 2026-03-25: Telegra.ph — списки без ul/ol

**Ошибка:**
Списки конвертировались как просто `<li>` элементы без оболочки `<ul>`.

**Результат:**
Пункты сливались: "Мониторить сотни источников одновременноВыделять ключевые события"

**Решение:**
Согласно официальной документации Telegra.ph:
- Списки должны быть в `<ul>` или `<ol>`
- `<li>` могут быть только детьми `<ul>`/`<ol>`
- Конвертер должен накапливать `li` в массив, затем оборачивать в `ul`

**Правильная структура:**
```json
{
  "tag": "ul",
  "children": [
    {"tag": "li", "children": ["Пункт 1"]},
    {"tag": "li", "children": ["Пункт 2"]}
  ]
}
```

**Правило:** Всегда оборачивай списки в `<ul>` для маркированных или `<ol>` для нумерованных.

### 2026-03-25: Telegra.ph — списки сливаются в параграф

**Ошибка:**
Пункты списков выводились слитно: "Мониторить сотни источников одновременноВыделять ключевые события"

**Результат:**
```
❌ Bad Request: can't parse entities
```

**Решение:**
1. Добавить пустую строку перед каждым списком
2. В конвертере закрывать параграф перед первым элементом списка
3. Использовать флаг `prev_was_list` для отслеживания

**Правило:** Перед списками всегда должна быть пустая строка в Markdown.

### 2026-03-25: Markdown V2 — символ `#`

**Ошибка:**
```python
publish("#тег")
```

**Результат:**
```
❌ Bad Request: can't parse entities
```

**Решение:**
```python
publish("\#тег")
```

**Правило:** Всегда экранируй `#` в тегах.

## 🎯 Общие принципы предотвращения ошибок

### 1. Проверяй перед публикацией

- Запусти `python3 publisher.py test` перед первой публикацией
- Проверь, что бот в администраторах канала

- Покажи черновик пользователю
- Получи подтверждение
- Только потом публикуй

### 3. Записывай ошибки

- Если ошибка произошла — запиши в этот файл
- Опиши проблему и решение
- Укажи дату

### 4. Читай перед запуском

- При каждом запуске читай этот файл
- Избегай повторения известных ошибок
