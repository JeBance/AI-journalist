# Протокол исследования

## 🔍 Этап 1: Определение приоритетов

Перед исследованием определи, какой тип публикации требуется:

| Тип | Описание | Приоритет источников |
|-----|----------|----------------------|
| **Daily digest** | Обзор 3-5 главных новостей за день | GitHub → RSS → Telegram |
| **Breaking news** | Одна срочная новость | Telegram → GitHub → RSS |
| **Deep dive** | Глубокий разбор одной темы | Блоги → GitHub → Документация |
| **Weekly summary** | Итоги недели (5-7 новостей) | Все источники, выбор лучших |

## 🌐 Этап 2: Сбор данных (последовательность)

### 2.1. GitHub (наивысший приоритет)

1. Открой `02_sources/02_github_repos.md`
2. Для каждого репозитория проверь **новые релизы** за последние 48 часов
3. Для критических репозиториев (Xray, php-src, node) проверь **коммиты**
4. Запиши найденное в `07_research_cache/03_temp_notes.md`

**Что искать:**
- Новые релизы (особенно major/minor версии)
- Security patches
- Breaking changes в changelog
- Новые фичи в release notes

### 2.2. RSS-ленты

1. Открой `02_sources/01_rss_feeds.md`
2. Посети каждую RSS-ленту (можно через ссылки)
3. Найди статьи за последние 48 часов
4. Оцени релевантность по ключевым словам из `02_sources/08_keywords.md`

**Приоритет RSS:**
1. Официальные блоги языков (PHP, JavaScript, CSS)
2. Технические блоги компаний (Cloudflare, Mozilla, GitHub)
3. Агрегаторы (Hacker News, Reddit)

### 2.3. Telegram-каналы

1. Открой `02_sources/03_telegram_channels.md`
2. Просмотри последние посты в каждом канале
3. Выдели уникальную информацию (которой нет в RSS/GitHub)

**Что искать:**
- Инсайды от разработчиков
- Быстрые анонсы
- Обсуждения уязвимостей
- Практические советы

### 2.4. Технические блоги

1. Открой `02_sources/04_technical_blogs.md`
2. Проверь новые статьи в официальных блогах
3. Ищи глубокие разборы, туториалы, case studies

### 2.5. Дополнительная проверка

При необходимости проверь:
- `02_sources/05_newsletters.md` — архивы рассылок
- `02_sources/06_podcasts_and_videos.md` — видео/аудио контент
- `02_sources/07_forums_and_communities.md` — обсуждения

## 📊 Этап 3: Анализ и отбор

### 3.1. Сбор всех находок

Собери все найденные новости в `07_research_cache/01_last_session.md`

### 3.2. Система приоритизации

| Приоритет | Критерии | Примеры |
|-----------|----------|---------|
| **Критическое** | Security-патчи, breaking changes, критические баги | CVE, уязвимости, падение производительности |
| **Важное** | Major/minor релизы, новые фичи, официальные анонсы | PHP 8.4, Node.js 23, Tailwind v4 |
| **Опциональное** | Туториалы, мнения, прогнозы, обзоры | "10 лучших практик...", "Почему я выбрал..." |

### 3.3. Проверка на уникальность

1. Открой `06_history/01_published_posts.md`
2. Открой `06_history/02_topics_covered.md`
3. Исключи темы, которые публиковались менее 30 дней назад
4. Исключи дубликаты одной и той же новости

### 3.4. Финальный отбор

Для **daily digest**: выбери 3-5 новостей разного приоритета
Для **single post**: выбери 1 новость критического/важного приоритета
Для **weekly summary**: выбери 5-7 лучших новостей недели

## 🔗 Этап 4: Документирование

Для каждой выбранной новости запиши:

```markdown
### {Заголовок}
- **Источник:** {название}
- **URL:** {ссылка}
- **Дата:** {дата публикации}
- **Категория:** {из 05_categories/}
- **Ключевые факты:**
  - факт 1
  - факт 2
- **Технические детали:** {версии, код, конфигурации}
- **Почему это важно:** {контекст для аудитории}
```

## ⏱️ Тайминги

| Этап | Ожидаемое время |
|------|-----------------|
| Полное исследование | 5-10 минут (в AI-времени) |
| Написание поста | 2-3 минуты |
| Проверка и публикация | 1 минута |
| **Итого** | **~10-15 минут** |
