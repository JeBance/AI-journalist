# Contributing — Как дополнять систему

## 📋 Назначение

Этот файл описывает, как вносить изменения и дополнения в инфраструктуру.

---

## 🎯 Общие принципы

### 1. Сохраняй структуру

- Не перемещай файлы без необходимости
- Сохраняй именование (`XX_filename.md`)
- Обновляй оглавления при добавлении файлов

### 2. Следуй стилю

- Используй Markdown
- Добавляй заголовки с эмодзи
- Сохраняй тон (экспертный, дружелюбный)

### 3. Документируй изменения

- Обновляй `09_meta/00_changelog.md`
- Добавляй дату изменения
- Описывай, что изменилось

---

## 📁 Добавление нового источника

### Шаг 1: Выбери категорию

Определи, к какой категории относится источник:
- `01_rss_feeds.md` — RSS/Atom ленты
- `02_github_repos.md` — GitHub репозитории
- `03_telegram_channels.md` — Telegram-каналы
- `04_technical_blogs.md` — Технические блоги
- `05_newsletters.md` — Email-рассылки
- `06_podcasts_and_videos.md` — Подкасты и видео
- `07_forums_and_communities.md` — Форумы и сообщества

### Шаг 2: Добавь запись

Используй формат:

```markdown
### {Название}
- **URL:** {ссылка}
- **Тип:** {RSS/GitHub/Telegram/Блог}
- **Приоритет:** {критический/высокий/средний/низкий}
- **Категория:** {категория из 05_categories/}
- **Описание:** {краткое описание}
```

### Шаг 3: Обнови статистику

В конце файла обнови итоговую таблицу:

```markdown
## 📊 Итого

| Приоритет | Количество |
|-----------|------------|
| Критический | X |
| Высокий | X |
| Средний | X |
| Низкий | X |
| **Всего** | **X** |
```

## 🐛 Исправление ошибок

### Шаг 1: Найди ошибку

- Опечатка
- Неверная ссылка
- Устаревшая информация

### Шаг 2: Исправь

- Внеси минимальные изменения
- Сохрани стиль файла

### Шаг 3: Задокументируй

Добавь запись в `09_meta/00_changelog.md`:

```markdown
## [1.0.1] — YYYY-MM-DD

### Исправлено

- {описание исправления}
```

- [ ] Оглавления обновлены

- [ ] Markdown корректен
- [ ] Стиль сохранён
- [ ] Changelog обновлён

---

## 📝 Процесс внесения изменений

1. **Форкни** репозиторий (если внешний контрибьютор)
2. **Создай ветку** `feature/xxx` или `fix/xxx`
3. **Внеси изменения**
4. **Проверь** чек-лист выше
5. **Создай Pull Request** (или просто закоммить)
6. **Опиши изменения** в PR/commit message

---

## 💡 Советы контрибьюторам

- **Начни с малого** — исправь опечатку, добавь источник
- **Смотри примеры** — используй существующие файлы как образец
- **Задавай вопросы** — если не уверен в чём-то
- **Тестируй** — проверь, что ссылки работают
- **Документируй** — обнови changelog
