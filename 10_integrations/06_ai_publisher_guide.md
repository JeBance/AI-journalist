# Инструкция для AI-агента по публикации статей

## 📋 Назначение

Эта инструкция описывает **формат входных данных** для скрипта публикации.

AI-агент должен сгенерировать данные в определённом формате и передать их скрипту.

---

##  Идеальный формат публикации

### Telegram (анонс)

```
🤖 [10 ситуаций, где ИИ уже работает: практическое руководство](https://telegra.ph/...)

Практическое руководство по применению нейросетей: от написания текстов до анализа данных.

Разбираем инструменты, возможности и ограничения.

#ai #технологии #практика #нейросети
```

**Под сообщением автоматически появляется превью статьи с кнопкой "Посмотреть".**

### Telegra.ph (статья)

- Заголовок отображается **только на странице статьи**
- Текст форматируется: **жирный**, _курсив_, списки
- Без видимых тегов HTML или символов Markdown

## 📥 Входные параметры для скрипта

### Формат 1: Аргументы командной строки

```bash
python3 /root/git/AI-journalist/publisher_final.py \
  --title "Заголовок статьи" \
  --description "Краткое описание (1-2 предложения)" \
  --content "@article.md" \
  --hashtags "ai,технологии,практика,нейросети" \
  --sources "MIT Technology Review,Stanford HAI"
```

### Формат 2: JSON файл

```json
{
  "title": "10 ситуаций, где ИИ уже работает: практическое руководство",
  "description": "Практическое руководство по применению нейросетей: от написания текстов до анализа данных.",
  "content": "Полный текст статьи в Markdown...",
  "hashtags": ["ai", "технологии", "практика", "нейросети"],
  "sources": ["MIT Technology Review", "Stanford HAI"],
  "author_name": "AI Journalist",
  "author_url": "https://t.me/JeBanceOnline"
}
```

```bash
python3 /root/git/AI-journalist/publisher_final.py --input article_data.json
```

## 📝 Требования к данным

### 1. Заголовок (`--title`)

**Обязательно:** строка

**Правила:**
- Максимум 80 символов (для красивого отображения в Telegram)
- Без специальных символов Markdown
- Без эмодзи (эмодзи добавляется автоматически по категории)

**Примеры:**
```
✅ "10 ситуаций, где ИИ уже работает: практическое руководство"
✅ "Node.js выпустил security патчи: 9 уязвимостей исправлены"
❌ "🔥 10 ситуаций где ИИ уже работает!!!"  # Эмодзи и восклицания
```

---

### 2. Описание (`--description`)

**Обязательно:** строка (2-3 предложения)

**Правила:**
- Краткое содержание статьи
- Без ссылок (ссылка добавляется автоматически из заголовка)
- Без хэштегов
- 2-3 предложения для красивого отображения

**Примеры:**
```
✅ "Практическое руководство по применению нейросетей: от написания текстов до анализа данных. Разбираем инструменты, возможности и ограничения."
✅ "Исправлены 9 уязвимостей в Node.js, включая 2 критических. Обновления получили все активные версии."
❌ "https://example.com #ai #news"  # Ссылки и хэштеги не нужны
```

---

### 3. Содержимое (`--content`)

**Обязательно:** текст в Markdown или `@file.md`

**Правила:**
- **Не включай заголовок** в начале (он добавляется автоматически)
- **Не включай первый параграф** который дублирует заголовок
- Используй Markdown для форматирования:
  - `## Заголовок` → Заголовок раздела
  - `**жирный**` → **жирный**
  - `_курсив_` → _курсив_
  - `· Пункт` → • Пункт списка
  - `[ссылка](url)` → ссылка

**Пример структуры:**
```markdown
Введение (2-3 предложения, без заголовка).

## Основная часть

Текст с **жирным** и _курсивом_.

· Пункт 1
· Пункт 2

## Заключение

Выводы.

---

Источники:
· Источник 1
· Источник 2
```

---

### 4. Хэштеги (`--hashtags`)

**Обязательно:** список через запятую

**Правила:**
- 3-5 хэштегов
- Без симвома `#` (добавляется автоматически)
- Первый хэштег определяет категорию и эмодзи

**Категории и эмодзи:**
```
ai, ai_tools → 🤖
javascript → 🟨
php → 🐘
css → 🎨
vpn, vpn_security, security → 🔒
hardware → 💻
devops → 🐳
databases → 🗄️
patterns → 📐
tutorial → 📚
news → 📰
```

**Примеры:**
```
✅ "ai,технологии,практика,нейросети"
✅ "javascript,security,nodejs"
❌ "#ai,#технологии"  # Без решётки
```

---

### 5. Источники (`--sources`)

**Опционально:** список через запятую

**Примеры:**
```
✅ "MIT Technology Review,Stanford HAI,Harvard Business Review"
✅ "Node.js Blog,GitHub Release Notes"
```

## ⚠️ Критические правила

### 1. Не дублируй заголовок в контенте

```markdown
❌ НЕПРАВИЛЬНО:
# 10 ситуаций, где ИИ уже работает  # Telegra.ph добавит это автоматически!

10 ситуаций, где ИИ уже работает...  # Дубль!

✅ ПРАВИЛЬНО:
Практическое руководство по применению нейросетей...  # Сразу контент
```

### 2. Не добавляй эмодзи в заголовок

```json
❌ НЕПРАВИЛЬНО:
"title": "🤖 10 ситуаций, где ИИ уже работает"

✅ ПРАВИЛЬНО:
"title": "10 ситуаций, где ИИ уже работает"
// Эмодзи добавится автоматически по категории
```

### 3. Не экранируй символы

```json
❌ НЕПРАВИЛЬНО:
"description": "Node\\.js выпустил обновления\\!"

✅ ПРАВИЛЬНО:
"description": "Node.js выпустил обновления!"
// Скрипт автоматически экранирует при публикации
```

### 4. Не добавляй ссылки в описание

```json
❌ НЕПРАВИЛЬНО:
"description": "Читайте на https://example.com"

✅ ПРАВИЛЬНО:
"description": "Практическое руководство по применению нейросетей."
// Ссылка добавится автоматически из заголовка
```

## 📊 Чек-лист перед публикацией

- [ ] Заголовок ≤ 80 символов
- [ ] Заголовок без эмодзи
- [ ] Описание 2-3 предложения
- [ ] Описание без ссылок и хэштегов
- [ ] Контент без заголовка в начале
- [ ] Контент использует Markdown для форматирования
- [ ] Хэштеги без символа `#`
- [ ] 3-5 хэштегов
- [ ] Источники указаны (если есть)
- [ ] JSON сохранён в UTF-8

## 🐛 Решение проблем

### Ошибка: "Bad Request: can't parse entities"

**Причина:** Проблемы с форматированием текста

**Решение:** Проверь, что в контенте нет:
- Непарных тегов `**`, `_`
- Неправильных ссылок `[текст](url`
- Специальных символов без экранирования

### Ошибка: "Title is required"

**Причина:** Пустой заголовок

**Решение:** Укажи `--title` или добавь `"title"` в JSON

### Ошибка: "No access token"

**Причина:** Не получен токен Telegra.ph

**Решение:**
```bash
python3 /root/git/AI-journalist-bot/get_telegraph_token.py
```
