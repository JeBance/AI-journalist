# Сценарий: Исследование по запросу

## 📋 Цель

Глубокое исследование конкретной темы по запросу пользователя.

**Время выполнения:** 20-30 минут  
**Частота:** По запросу  
**Сложность:** Средняя

---

## 🔄 Шаги выполнения

### Шаг 1: Получение запроса (1 минута)

Пользователь формулирует запрос:

```
Исследуй тему «{тема}» и напиши пост
```

**Примеры запросов:**
- «Исследуй новые возможности PHP 8.5»
- «Разберись с VLESS Reality и напиши туториал»
- «Изучи сравнение Prisma и Doctrine»

### Шаг 2: Уточнение требований (1 минута)

Уточни у пользователя:

1. **Тип поста:** single_post, tutorial, comparison, code_review?
2. **Целевая аудитория:** Junior, Middle, Senior?
3. **Глубина:** поверхностный обзор или глубокий разбор?
4. **Дедлайн:** когда нужен результат?

### Шаг 3: Планирование исследования (2 минуты)

Составь план исследования:

```markdown
### План исследования

**Тема:** {тема}

**Источники для проверки:**
1. GitHub — {репозитории}
2. RSS — {ленты}
3. Блоги — {сайты}
4. Документация — {ссылки}

**Ключевые аспекты:**
- {аспект 1}
- {аспект 2}
- {аспект 3}
```

### Шаг 4: Глубокое исследование (10-15 минут)

#### 4.1. GitHub (3 минуты)

1. Найди релевантные репозитории
2. Проверь:
   - Последние релизы
   - Open/closed issues
   - Recent commits
   - Discussions
3. Запиши находки в `07_research_cache/03_temp_notes.md`

#### 4.2. Документация (3 минуты)

1. Открой официальную документацию
2. Найди разделы по теме
3. Проверь changelog, release notes
4. Выпиши ключевые изменения

#### 4.3. Технические блоги (5 минут)

1. Найди статьи по теме
2. Прочитай 3-5 качественных материалов
3. Сравни разные точки зрения
4. Выпиши цитаты и примеры

#### 4.4. Сообщества (3 минуты)

1. Проверь Reddit (r/programming, тематические сабреддиты)
2. Проверь Hacker News
3. Проверь Dev.to, Medium
4. Выпиши мнения и опыт использования

#### 4.5. Видео и подкасты (опционально, 5 минут)

1. YouTube (официальные каналы, конференции)
2. Подкасты (Syntax, Laravel News, etc.)
3. Выпиши ключевые моменты

### Шаг 5: Анализ и синтез (5 минут)

1. Собери все заметки в `07_research_cache/03_temp_notes.md`
2. Структурируй информацию:
   - Факты
   - Мнения
   - Примеры кода
   - Best practices
3. Выдели главное для поста
4. Отбрось лишнее

### Шаг 6: Написание поста (5-10 минут)

1. Выбери шаблон из `03_templates/`:
   - `01_single_post.md` — новость
   - `04_tutorial.md` — инструкция
   - `05_code_review.md` — разбор кода
   - `06_comparison.md` — сравнение
2. Напиши пост по шаблону
3. Добавь примеры кода
4. Добавь ссылки на источники
5. Добавь теги из `05_categories/`

### Шаг 7: Проверка качества (2 минуты)

Пройди чек-лист из `01_system_prompts/04_quality_checklist.md`:

- [ ] Фактологичность
- [ ] Актуальность
- [ ] Уникальность
- [ ] Полнота
- [ ] Структура
- [ ] Форматирование
- [ ] Стиль

### Шаг 8: Показ черновика (1 минута)

Покажи пост пользователю:

```
Готовый пост:

{текст поста}

---

✅ Чек-лист пройден
📊 Оценка качества: {X}/5
🔗 Источников: {N}
📝 Категория: {category}
🏷️ Теги: {tags}

Опубликовать этот пост в Telegram?
```

### Шаг 9: Публикация и запись (2 минуты)

1. После подтверждения — опубликуй (см. `01_daily_publication.md`, шаг 6-7)
2. Запиши в историю:
   - `06_history/01_published_posts.md`
   - `06_history/02_topics_covered.md`
3. Обнови research cache

### Шаг 10: Отчёт об исследовании (1 минута)

Создай краткий отчёт:

```markdown
### Отчёт об исследовании

**Тема:** {тема}
**Дата:** YYYY-MM-DD
**Время:** {X} минут
**Источников проверено:** {N}
**Пост опубликован:** {ссылка}

**Ключевые находки:**
- {находка 1}
- {находка 2}

**Рекомендации:**
- {рекомендация 1}
```

## 💡 Советы

- **Не бойся задавать вопросы** — уточнение экономит время
- **Используй несколько источников** — для объективности
- **Проверяй даты** — информация должна быть актуальной
- **Сохраняй заметки** — для будущих исследований
