# Сценарий: Срочная новость

## 📋 Цель

Быстро опубликовать критическую новость (security patch, breaking change, incident).

**Время выполнения:** 5-10 минут  
**Частота:** По необходимости  
**Сложность:** Низкая

---

## 🚨 Когда использовать

Используй этот сценарий для:

| Ситуация | Пример |
|----------|--------|
| **Критическая уязвимость** | CVE-2026-XXXXX в популярной библиотеке |
| **Security patch** | Срочное обновление безопасности |
| **Breaking change** | Изменение, ломающее обратную совместимость |
| **Инцидент** | Отключение сервиса, outage |
| **Внезапный анонс** | Неожиданный релиз важной технологии |

---

## 🔄 Шаги выполнения

### Шаг 1: Получение информации (1 минута)

Пользователь сообщает о срочной новости:

```
Срочно! {описание новости}
```

**Или AI обнаруживает:**
- Мониторинг GitHub Security Advisory
- Telegram-каналы с срочными новостями
- RSS-ленты с security updates

### Шаг 2: Быстрая проверка (2 минуты)

#### 2.1. Подтверждение источника

1. Найди оригинальный источник:
   - GitHub Security Advisory
   - Официальный блог проекта
   - Официальный Twitter/X
2. Убедись, что информация достоверна

#### 2.2. Оценка критичности

| Уровень | Критерии | Действие |
|---------|----------|----------|
| **Критический** | CVE, exploit в дикой природе, данные под угрозой | Публиковать немедленно |
| **Высокий** | Security patch, breaking change | Публиковать в течение часа |
| **Средний** | Важный релиз, но не срочный | Использовать daily publication |

### Шаг 3: Сбор информации (2 минуты)

Собери ключевые факты:

```markdown
### Факты

**Что случилось:** {краткое описание}
**Кто затронут:** {аудитория}
**Версии:** {затронутые версии}
**CVE:** {номер, если есть}
**Источник:** {ссылка}
**Что делать:** {рекомендации}
```

### Шаг 4: Написание поста (2-3 минуты)

Используй шаблон `03_templates/03_breaking_news.md`:

```
🚨 **СРОЧНО**

{суть в одном предложении}

---

⚡ *Что случилось*

{детали: 2-4 предложения}

---

🎯 *Кто затронут*

{аудитория: кто должен обратить внимание}

---

🔧 *Что делать*

{конкретные шаги: 1, 2, 3}

---

🔗 *Источники*

· {название источника}

#breaking #security #теги
```

**Требования:**
- Краткость (100-200 слов)
- Конкретные инструкции
- Без паники
- Только факты

### Шаг 5: Быстрая проверка (1 минута)

Проверь минимальный чек-лист:

- [ ] Факты проверены по источнику
- [ ] Есть конкретные инструкции «Что делать»
- [ ] Указаны затронутые версии
- [ ] Тон серьёзный, без паники
- [ ] Источник указан

### Шаг 6: Показ черновика (1 минута)

Покажи пост пользователю:

```
🚨 СРОЧНЫЙ ПОСТ

{текст поста}

---

⚡ Критичность: {высокая/средняя}
🔗 Источник: {ссылка}
⏱️ Время на проверку: 1 минута

Опубликовать немедленно?
```

**Важно:** Для срочных новостей пользователь обычно подтверждает быстро.

### Шаг 7: Публикация (1 минута)

1. После подтверждения — опубликуй немедленно
2. Не трать время на идеальное форматирование
3. Главное — скорость и точность

### Шаг 8: Запись в историю (1 минута)

1. Добавь в `06_history/01_published_posts.md`:

```markdown
### [YYYY-MM-DD] {Заголовок}
- **Категория:** {категория}
- **Шаблон:** breaking_news
- **Ключевые темы:** {теги}
- **Источники:** 
  - {название} ({URL})
- **Telegram ID:** {id}
- **Статус:** опубликован
---
```

2. Добавь в `06_history/02_topics_covered.md` (если тема уникальна)

### Шаг 9: Follow-up (опционально)

Через несколько часов или на следующий день:

1. Проверь обновления по теме
2. Если есть новая информация — напиши обновление
3. Если тема развилась — напиши подробный пост

| Количество постов | 1 (краткий) |
| Количество источников | 1-2 (оригинальные) |
| Скорость реакции | < 15 минут |

---

## ⚠️ Важные предупреждения

### Не публикуй, если:

- ❌ Информация из непроверенного источника
- ❌ Это слухи без подтверждения
- ❌ Не можешь найти оригинальный источник
- ❌ Информация противоречива

### Всегда указывай:

- ✅ Оригинальный источник
- ✅ Дату/время информации
- ✅ Уровень уверенности (если неподтверждённое)

---

## 💡 Советы

- **Скорость важна, но точность важнее** — не публикуй непроверенное
- **Конкретные инструкции** — люди должны знать, что делать
- **Без паники** — серьёзный тон, но не алармизм
- **Follow-up** — обновляй информацию по мере поступления
