## 🏆 Пример 4: Туториал

```
⚙️ *Настройка VLESS с Reality за 10 минут*

Пошаговая инструкция по настройке современного и безопасного протокола VLESS с Reality\. Время: ~10 минут\.

---

📋 *Что понадобится*

· Сервер с Ubuntu 22.04+
· Домен,指向щий на сервер
· Xray-core установлен

⏱️ *Время:* 10 минут

---

### Шаг 1: Генерация ключей

Сгенерируем приватный ключ для Reality:

```bash
xray x25519
```

Получим что-то вроде:

```
Private key: {private_key}
Public key: {public_key}
```

Сохраните оба ключа — они понадобятся в конфиге\.

---

### Шаг 2: Создание конфига

Создайте файл `/usr/local/etc/xray/config.json`:

```json
{
  "inbounds": [{
    "port": 443,
    "protocol": "vless",
    "settings": {
      "clients": [{
        "id": "{uuid}",
        "flow": "xtls-rprx-vision"
      }],
      "decryption": "none"
    },
    "streamSettings": {
      "network": "tcp",
      "security": "reality",
      "realitySettings": {
        "dest": "example.com:443",
        "serverNames": ["example.com"],
        "privateKey": "{private_key}"
      }
    }
  }]
}
```

---

### Шаг 3: Запуск Xray

```bash
systemctl restart xray
systemctl status xray
```

Убедитесь, что сервис активен\.

---

✅ *Проверка результата*

Проверим, что порт слушается:

```bash

```

Подключитесь клиентом с конфигом (см. источники)\.

---

🔍 *Что мы узнали*

· Reality маскирует трафик под обычный HTTPS
· VLESS не требует шифрования на уровне протокола
· Настройка занимает менее 10 минут

---

## 🏆 Пример 5: Code Review

```
🔍 *Property Hooks в PHP 8.4: разбор новой фичи*

PHP 8.4 вводит property hooks — механизм переопределения доступа к свойствам\. Разберём, как это работает\.

---

📄 *Исходный код*

```php
class User {
  public string $email {
    get => $this->email;
    set {
      if (!filter_var($value, FILTER_VALIDATE_EMAIL)) {
        throw new InvalidArgumentException('Invalid email');
      }
      $this->email = strtolower(trim($value));
    }
  }
  
  public readonly string $name;
  
  public function __construct(string $email, string $name) {
    $this->email = $email;
    $this->name = $name;
  }
}
```

---

🔍 *Анализ*

**Property hook `get`:** Возвращает значение без изменений\. В данном случае можно было опустить — будет использоваться по умолчанию\.

**Property hook `set`:** Валидирует и нормализует email при присваивании\. Это заменяет необходимость в отдельном сеттере\.

**`readonly $name`:** Свойство только для чтения, устанавливается в конструкторе\.

---

✅ *Что хорошо*

· Валидация инкапсулирована в свойстве
· Нет необходимости в отдельных методах
· Код становится декларативнее

⚠️ *Что можно улучшить*

· В `get` можно добавить форматирование (для отображения)
· Рассмотреть использование Value Objects для email

---

💡 *Лучшая практика*

Для сложной логики выноси в отдельные методы:

```php
class User {
  public string $email {
    get => $this->email;
    set => $this->email = $this->normalizeEmail($value);
  }
  
  private function normalizeEmail(string $email): string {
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
      throw new InvalidArgumentException('Invalid email');
    }
    return strtolower(trim($email));
  }
}
```

**Почему лучше:**
- Логика валидации тестируется отдельно
- Метод можно переиспользовать
- Чёткое разделение ответственности

---

📚 *Применение в проекте*

Используй property hooks для:
- Валидации данных при присваивании
- Нормализации значений (trim, strtolower)
- Логирования доступа к свойствам
- Вычисляемых свойств без геттеров

---

🔗 *Источники*

· [PHP 8.4 RFC: Property Hooks](https://wiki.php.net/rfc/property-hooks)
· [PHP.net Documentation](https://www.php.net/manual/ru/)

#codereview #php #patterns
```

**Почему это хороший пост:**
- ✅ Реальный пример кода
- ✅ Построчный анализ
- ✅ Баланс положительного и критики

## 🏆 Пример 6: Comparison

```
⚖️ *Prisma vs Doctrine ORM: что выбрать для PHP?*

Две популярные ORM для PHP: Prisma (TypeScript-first) и Doctrine (классика PHP)\. Сравниваем для выбора в новом проекте\.

---

📊 *Краткое сравнение*

| Критерий | Prisma | Doctrine |
|----------|--------|----------|
| Производительность | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| Сложность | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| Экосистема | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| Сообщество | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| Типизация | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

---

### Prisma ORM

**Плюсы:**

· Автоматическая генерация типов TypeScript
· Интуитивный API и query builder
· Миграции из коробки
· Отличная документация

**Минусы:**

· Меньше зрелости (новее на рынке)
· Оверкилл для простых проектов
· Node.js требуется для генерации

**Когда выбирать:**

· Новый проект с TypeScript
· Команда знакома с Node.js экосистемой
· Важна скорость разработки

---

### Doctrine ORM

**Плюсы:**

· Зрелая и проверенная (с 2006 года)
· Огромная экосистема и сообщество
· Гибкость и настраиваемость
· Работает в чистом PHP

**Минусы:**

· Сложнее в освоении
· Больше boilerplate кода
· Медленнее разработка

**Когда выбирать:**

· Legacy проект или миграция
· Команда знает Doctrine
· Требуется максимальная гибкость

---

🏆 *Итог*

**Выбирай Prisma, если:**
- Новый проект на PHP + TypeScript
- Хочешь современную DX
- Команда готова изучать новое

**Выбирай Doctrine, если:**
- Legacy проект или команда знает Doctrine
- Нужна максимальная гибкость
- Проект на чистом PHP

---

🔗 *Источники*

· [Doctrine Documentation](https://www.doctrine-project.org/)
