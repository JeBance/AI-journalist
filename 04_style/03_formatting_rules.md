# Правила форматирования (Telegram Markdown V2)

## 📋 Основы Telegram Markdown V2

Telegram поддерживает **Markdown V2** для форматирования текста.

### Поддерживаемые элементы

| Элемент | Синтаксис | Пример |
|---------|-----------|--------|
| **Жирный** | `*текст*` | `*важно*` → **важно** |
| _Курсив_ | `_текст_` | `_акцент_` → _акцент_ |
| `Моноширинный` | `` `текст` `` | `` `код` `` → `код` |
| [Ссылка](url) | `[текст](url)` | `[Google](https://google.com)` |
| ```код``` | ```` ```код``` ```` | Блок кода |
| ||Спойлер|| | `||текст||` | ||скрыто|| |

---

## ⚠️ Экранирование специальных символов

В Markdown V2 **обязательно экранируй** эти символы:

```
_ * [ ] ( ) ~ ` > # + - = | { } . !
```

Добавляй обратный слэш `\` перед символом.

### Примеры экранирования

**❌ Неправильно:**
```
PHP 8.4 > PHP 8.3
Список:
·Item 1
·Item 2
```

**✅ Правильно:**
```
PHP 8.4 \> PHP 8.3
Список:
·Item 1
·Item 2
```

## 📝 Форматирование заголовков

### Заголовок поста

```
*Заголовок — максимум 80 символов*
```

**Пример:**
```
🔥 *PHP 8.4.0 released: property hooks и без скобок для new*
```

### Подзаголовки в тексте

```
### 📌 Суть

### 💻 Технические детали

### 🔍 Что это значит для вас
```

**Важно:** В Telegram нет нативных заголовков. Используй жирный + эмодзи.

## 📄 Форматирование кода

### Встроенный код

Для имён переменных, функций, версий:

```
Используй `new User()` вместо конструктора
Версия `1.8.24` содержит исправления
```

### Блок кода

Для многострочного кода:

````
```json
{
  "protocol": "vless",
  "settings": {...}
}
```
````

**Примеры языков:**
- `javascript` / `js`
- `typescript` / `ts`
- `php`
- `python`
- `bash` / `shell`
- `json`
- `yaml`
- `sql`
- `css`
- `html`

## 🔗 Форматирование ссылок

### Правильный формат

```
[текст ссылки](url)
```

**Примеры:**
```
[Официальный релиз](https://github.com/XTLS/Xray-core/releases)
[Документация PHP](https://www.php.net/manual/ru/)
```

### ⚠️ Источники должны быть кликабельными

**В секции «Источники» используй только кликабельные ссылки:**

**❌ Неправильно (текст без ссылки):**
```
🔗 Источники

· Официальный релиз на GitHub
· PHP.net Release Announcement
```

**✅ Правильно (кликабельная ссылка):**
```
🔗 Источники

· [Официальный релиз на GitHub](https://github.com/XTLS/Xray-core/releases/tag/v1.8.24)
· [PHP.net Release Announcement](https://www.php.net/releases/8.4/)
```

### ⚠️ КРИТИЧНО: Подчёркивания `_` в URL не должны становиться курсивом

URL-адреса часто содержат символ `_` (например, `the_end_of_kubernetes`).
Если курсив обрабатывается **до** ссылок, такие URL разбиваются на части,
и ссылка перестаёт работать.

**Правило для кода:** порядок обработки inline-форматирования строго:
1. Жирный `**текст**`
2. **Ссылки** `[текст](url)` ← ДО курсива!
3. Курсив `_текст_`
4. Код `` `текст` ``

**Правило для генерации контента (AI):**
- Никогда не оборачивай части URL в `_` как курсив
- Если источник содержит `_` в названии (напр., `r/kubernetes`),
  пиши название без подчёркиваний: `Reddit r/kubernetes`, а не `Reddit r/_kubernetes_`

**❌ Неправильно (сломанная ссылка):**
```
[Reddit r/_kubernetes_](https://reddit.com/r/kubernetes/some_end_of_article_url/)
```
Результат: URL будет разбит на `https://reddit.com/r/kubernetes/some` + `<i>end</i>` + `of_article_url/`

**✅ Правильно:**
```
[Reddit r/kubernetes](https://reddit.com/r/kubernetes/some_end_of_article_url/)
```

### Чего избегать

**❌ Неправильно:**
- Голые URL: `https://example.com`
- «Нажмите здесь»: [здесь](url)

**✅ Правильно:**
- Описательный текст: [Официальный релиз](url)
- Короткие URL для известных доменов: [GitHub](https://github.com/...)

## 📋 Списки

### Маркированные списки

Используй символ `·` (middle dot, U+00B7):

```
· Пункт 1
· Пункт 2
· Пункт 3
```

**Почему не `-` или `*`:**
- `-` и `*` требуют экранирования
- `·` выглядит аккуратнее в Telegram

### Нумерованные списки

```
1\. Первый шаг
2\. Второй шаг
3\. Третий шаг
```

**Важно:** Точка после цифры требует экранирования `\.`

## ✨ Дополнительные элементы

### Разделители

Используй `---` для визуального разделения секций:

```
{секция 1}

---

{секция 2}
```

### Спойлеры

Для скрытия информации (например, ответы, сюрпризы):

```
||Скрытый текст||
```

Отображается как размытый блок, открывается по тапу.

## 🚫 Частые ошибки

### 1. Отсутствие экранирования

**❌:**
```
PHP 8.4 > PHP 8.3
Список:
- Item 1
- Item 2
```

**✅:**
```
PHP 8\.4 \> PHP 8\.3
Список:
· Item 1
· Item 2
```

### 2. Неправильные блоки кода

**❌:**
```
```
код без указания языка
```
```

**✅:**
```
```php
код с указанием языка
```
```

### 3. Битые ссылки

**❌:**
```
[ссылка](https://example.com без закрывающей скобки)
```

**✅:**
```
[ссылка](https://example.com)
```
