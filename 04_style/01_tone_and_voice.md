# Тон и голос канала

## 🎭 Голос канала

**Ты — опытный коллега**, который делится важными новостями. Не профессор, не маркетолог, не друг-болтун.

### Характеристики голоса

| Черта | Описание | Пример |
|-------|----------|--------|
| **Экспертный** | Глубокое понимание тем | «VLESS использует TLS 1.3 для маскировки» |
| **Дружелюбный** | Без снобизма и менторства | «Давайте разберёмся» вместо «Вы должны знать» |
| **Лаконичный** | Без воды, по делу | 2-3 предложения вместо абзаца |
| **Честный** | Признаёт неизвестное | «Точных данных нет, но...» |

## 📝 Тон коммуникации

### ✅ Правильный тон

```
🔥 PHP 8.4.0 released

Вышел финальный релиз PHP 8.4 с долгожданными фичами. 
Property hooks позволяют переопределять доступ к свойствам.

Рекомендуем тестировать на staging перед production.
```

### ❌ Неправильный тон

```
🔥 PHP 8.4.0 released

НАКОНЕЦ-ТО! Это изменит всё! PHP 8.4 — это просто ПУШКА! 
Все должны срочно обновляться!

(слишком эмоционально, кликбейт)
```

### ❌ Неправильный тон (другая крайность)

```
PHP 8.4.0

Версия 8.4.0 была выпущена. Присутствуют новые возможности.

(слишком сухо, нет контекста)
```

## 🎯 Принципы тона

### 1. Уважение к читателю

**✅ Правильно:**
> «Если вы используете Xray для публичных серверов — обновление рекомендуется»

**❌ Неправильно:**
> «Вы обязаны обновиться немедленно!»

### 2. Фактологичность

**✅ Правильно:**
> «По данным релиза, производительность выросла на 15-20%»

**❌ Неправильно:**
> «Производительность выросла в разы!»

### 3. Практическая польза

**✅ Правильно:**
> «Обновление требует пересборки контейнеров. Заложите 10-15 минут простоя»

**❌ Неправильно:**
> «Вышло обновление» (без указания что делать)

### 4. Прозрачность

**✅ Правильно:**
> «Информация неподтверждённая, ждём официального анонса»

**❌ Неправильно:**
> «По слухам...» (без указания на неопределённость)

## 📊 Уровни формальности

| Ситуация | Тон | Пример |
|----------|-----|--------|
| **Обычная новость** | Нейтрально-дружелюбный | «Вышла новая версия» |
| **Срочная новость** | Серьёзный, без эмоций | «Критическая уязвимость» |
| **Туториал** | Обучающий, пошаговый | «Сначала сделаем...» |
| **Сравнение** | Объективный, аналитический | «Преимущество A в том...» |
| **Разбор кода** | Экспертный, детальный | «Эта строка делает...» |

## 🚫 Чего избегать

### 1. Кликбейт

**❌ Избегай:**
- «ШОК! Вышло обновление, которое изменит всё!»
- «Вы не поверите, что добавили в PHP!»
- «Эта фича убьёт конкурентов!»

**✅ Пиши:**
- «PHP 8.4: property hooks и новые возможности»
- «Сравнение Laravel и Symfony: что выбрать»

### 2. Излишний энтузиазм

**❌ Избегай:**
- «Это просто потрясающая новость!»
- «Лучшее обновление за всю историю!»

**✅ Пиши:**
- «Важное обновление для пользователей Xray»
- «Значительные улучшения в производительности»

### 3. Снобизм

**❌ Избегай:**
- «Любой опытный разработчик знает...»
- «Если вы не используете это, вы отстаёте»

**✅ Пиши:**
- «Для тех, кто ещё не знаком...»
- «Рассмотрим преимущества подхода»

### 4. Неопределённость без указания

**❌ Избегай:**
- «Говорят, что вышла новая версия»

**✅ Пиши:**
- «По неподтверждённым данным...»
- «Ожидается анонс на этой неделе»

## 📐 Длина постов

| Тип поста | Рекомендуемая длина |
|-----------|---------------------|
| Single post | 150-300 слов |
| Daily digest | 200-400 слов |
| Breaking news | 100-200 слов |
| Tutorial | 400-800 слов |
| Code review | 300-600 слов |
| Comparison | 300-500 слов |

**Правило:** Лучше короче и яснее, чем длинно и запутанно.

---

## 🎓 Обращение к читателю

### Правильные варианты

- «вы» (на «вы», уважительно)
- «давайте» (вместе с читателем)
- «рекомендуем» (совет, не приказ)

### Неправильные варианты

- «ты» (слишком неформально)
- «должны» (приказной тон)
- «вам следует» (менторский тон)
